Checkpoint: GCGP T_amb=20 anomaly root-cause confirmed; compressor bug-hunt trail fully documented

Phase 4 cross-method comparison (task #37) was showing a +7.65% COP
deviation vs. the validated Helmholtz baseline for GCGP specifically at
T_amb=20 C, a regression from an earlier ~0% agreement. This commit is
a checkpoint of the full investigation: six fix attempts (passes 4-9),
all tried and reverted after either breaking other GCGP ambients or
catastrophically breaking the NIST baseline, followed by a direct,
confirmed diagnosis of the actual root cause. No model behavior has
changed from the last known-good, fully-validated state -- every
attempted change in vapor_compression_cubic.py is fully reverted; this
commit's value is the diagnostic trail and tooling, not a behavior fix.

Root cause (confirmed, not theorized):
- Built entropy_dome_proximity_check.py, which compares each method's
  already-solved compressor isentropic-block entropy (entr_mol) against
  the entropy its own equation of state predicts for pure vapor at that
  same state (entr_mol_phase["Vap"]) and pure liquid (["Liq"]).
- GCGP: T10/T15/T25 all land on a single real EoS root (entr_mol exactly
  equals entr_mol_phase["Vap"], zero ambiguity). T20 -- and ONLY T20 --
  lands on a genuine two-phase blend (entr_mol sits strictly between the
  vapor and liquid roots, mathematically requiring phase_frac to be a
  real fraction between 0 and 1, not 1.0). This is a direct, reproducible
  consequence of GCGP's fitted (Pc, Tc, omega) placing its own saturation
  dome differently than real R-32 at this specific operating point, not
  a numerical fluke isolated to one unlucky ambient.
- NIST shows a separate, more widespread blending pattern (present at
  T10/T15/T20, clean only at T25) that does NOT measurably hurt its COP
  accuracy -- confirms this is a different, unrelated mechanism that
  should not be chased together with GCGP's issue.

Fix-attempt trail (all reverted, kept for the record):
- Pass 5: activated a T_out >= T_isen constraint. Fixed the GCGP T20
  sign flip in isolation but regressed NIST across the grid. Reverted.
- Pass 6: anchored the isentropic block's temperature bound to CoolProp's
  real-R32 saturation temperature. Invalid for GCGP/SPGP, which
  deliberately fit different critical properties than real R32 (~72K gap
  found). Reverted without needing a full-grid test.
- Pass 7: tightened the isentropic block's temperature bound around its
  own warm-started value instead of a flat Tsat-derived range. Partial
  improvement for GCGP but spread the T_out/T_isen inconsistency to 3 of
  4 ambients. Reverted.
- Pass 8: fixed phase_frac["Vap"]=1.0 inside the isolated warm-start
  solve in _initialize_compressor_with_retry(). Initially misjudged as
  harmless (single-point comparison looked unaffected); later proven to
  independently corrupt NIST T_amb=20 (COP=484980, nonsensical) even
  after passes 7 and 9 were reverted. Fully reverted; the earlier
  "harmless" comment in the code has been corrected to match.
- Pass 9: fixed phase_frac["Vap"]=1.0 in the coupled solve, combined with
  pass 7's bound. Fixed the T_out/T_isen consistency symptom for GCGP but
  landed on a different, colder, still-wrong branch (severe GCGP T15
  outlier, -34% vs Helmholtz) AND catastrophically broke NIST T_amb=20
  (COP=-12980, nonsensical). Decisively reverted.
- Restored and reconfirmed the fully-original pass-1/2/2b/3-only
  baseline for both comp_isen_state and comp_out_state bounds --
  verified against NIST's full known-good grid (3.5677/3.3974/3.1316/
  2.8005) and GCGP's original diagnosis numbers exactly.
